# Quant-Lab 개선 계획

이 문서는 저장소 코드를 기준으로 정리한 개선 후보입니다. 실제 서비스의 현재 동작이나 투자 성과를 검증한 결과는 아닙니다.

## 목표

금융 리포트를 찾고 검토하는 과정을 보조하는 도구로서, **원문 확인이 가능한 요약과 검토 기록**을 제공한다. AI의 출력은 근거를 확인해야 하는 초안으로 취급한다.

## 현재 흐름

1. `services/search_service.py`에서 설정된 키워드와 사이트에 맞는 PDF를 검색한다.
2. `services/crawler_service.py`에서 최대 앞 10쪽의 텍스트를 추출한다.
3. `daily_job.py`에서 개별 요약과 종합·번역을 수행하고 DB에 저장한 뒤 구독자에게 발송한다.
4. `main.py`에서 최신 종합 리포트를 표시한다.

## 먼저 해결할 문제

| 문제 | 현재 코드의 근거 | 개선 방향 |
| --- | --- | --- |
| 종합 결과의 원문 추적 어려움 | 개별 저장 데이터에 링크는 있으나 종합 프롬프트에는 제목과 요약만 전달한다. | 각 자료의 ID·원문 링크·발행일을 함께 전달하고 결과에서 해당 자료를 참조하도록 설계한다. 링크와 날짜는 누락 가능성을 명시한다. |
| 근거 없는 투자 판단 유도 가능성 | `config/prompts.py`는 종목코드 변환, 역발상 아이디어, Top Picks를 강제한다. | 원문에 없는 종목·수치·의견은 생성하지 않도록 바꾸고, 근거가 부족하면 명시적으로 생략한다. 결과를 사실·원문 의견·해석으로 구분한다. |
| 수집 범위와 신선도 | 검색어가 `Infrastructure Outlook`으로 고정되어 있으며 PDF 앞 10쪽만 처리한다. 검색 시점 제한이 문서의 실제 발행일 검증을 뜻하지는 않는다. | 주제별 검색 설정을 분리하고 발행일·추출 범위·실패 사유를 표시한다. |
| 재현 및 품질 검증 부족 | 의존성 버전이 고정되지 않았고 DB 스키마와 샘플 데이터가 저장소에 없다. | 테스트용 가상 자료와 DB 설정 절차, 의존성 버전, 외부 연결 없는 검증을 준비한다. |
| 자동 작업의 운영 영향 | `daily_job.py`는 DB 저장과 구독자 이메일 발송을 수행한다. | 발송 없는 검토 모드를 설계하고, 변경 테스트는 운영 DB·실제 수신자와 분리한다. |

## 단계별 작업

1. **재현 가능한 기준 마련**: 현재 실행 환경·DB 스키마를 확인하고, 합성 자료를 이용해 검색 결과부터 요약까지의 테스트 사례를 만든다.
2. **근거 연결**: 문서별 ID, 제목, URL, 확인 가능한 발행일, 추출 범위를 보존하고 출력의 주장과 출처를 연결한다. 원문에 없는 값은 미확인으로 남긴다.
3. **품질 평가**: 소규모 자료를 직접 검토해 출처 연결 정확성, 수치 일치, 중요 내용 누락, 근거 없는 주장, 처리 실패를 기록한다. 개선 전후에 동일 자료로 비교한다.
4. **검토 중심 화면**: 요약 옆에서 출처와 근거를 열어보고 사용자가 수정·승인할 수 있는 흐름을 검토한다. 실제 발송 전에는 별도 승인 단계를 둔다.
5. **포트폴리오 정리**: 해결하려는 업무, 본인의 기여와 AI 활용 방식, 설계 선택, 평가 결과 및 한계를 사실에 맞게 기록한다. 측정하지 않은 시간 절감이나 수익률은 주장하지 않는다.

## 미확인 사항

- 운영 중인 서비스와 배포 상태, 실제 이용자 및 구독자 수
- DB 스키마와 접근 권한, 현재 외부 API의 사용 가능 여부
- 리포트 원문의 재배포·저장 및 이용 조건
- 프로젝트에서 각 참여자가 수행한 역할과 구현 방식

위 항목은 코드만으로 확정하지 않는다.
